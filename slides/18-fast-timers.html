What a native setTimeout costs

No libuv handle per timer: one libuv timer per thread. But every call still:

Allocates a Timeout~13 fields, plus an args array if you pass arguments
Tracks async contextAsync id, trigger id and context frame per timer
Reads the clockgetLibuvNow() on insert
Maintains listsA linked list per duration plus a priority queue
10,000connections × 1 idle timeout = 10,000 long-lived objects, promoted and traced on every major GC

Pooled timers

import { setTimeout, clearTimeout } from '@nxtedition/timers'

// ≥ 1 s: one shared 500 ms tick scans a flat array
const handle = setTimeout(onIdle, 30_000, conn)  // no closure

// < 1 s: falls through to the native setTimeout
const fast = setTimeout(onTick, 50)

clearTimeout(handle)
clearTimeout(fast)

Trade-offs: up to one tick late, and callbacks don't carry AsyncLocalStorage context.

How it works internally (simplified)

function dispatch () {                      // runs every 500 ms
  const now = Math.round(performance.now() - origin)   // stays a Smi
  while (index < timers.length) {
    const t = timers[index]
    if (t.deadline <= now) {
      swapRemove(timers, index)             // O(1)
      t.callback(t.opaque)                  // opaque, not a closure
    } else index++
    if ((++n & 0xff) === 0 && shouldYield()) return doYield(dispatch)   // every 256 timers
  }
  index = 0
}
