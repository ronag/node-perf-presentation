A Cache Without a Linked List

Map for lookups + an intrusive array + two random choices for eviction

The problems with LRU

Typical LRU: a Map for lookup plus a doubly linked list for recency.

Overhead per entryA { key, value, prev, next } node for every entry: allocation, GC, pointer chasing.
Work per hitEvery read unlinks and relinks a node at the head.
ScansIterating a data set larger than the cache flushes all of it: hit rate drops to 0%.

Power of two random choices

Keep no order at all. To evict, sample two random entries and drop the less recently used one.

Near-LRU hit rateMatches or beats LRU for larger caches (danluu.com/2choices-eviction).
Degrades gracefullyRandom victims leave some hot entries behind under scans, where LRU drops to 0%.
O(1), no nodesA tick counter per item, swap-remove from a dense array.
IntrusiveThe item carries its index, tick and key. Nothing extra to allocate.

Implementation: structure and get()

class Item { [kIdx] = -1; [kTick] = 0; [kKey] = undefined }

class FastCache {
  #map = new Map()   // key → item
  #arr = []          // items, unordered (swap-remove)
  #tick = 0
  get (key) {
    const item = this.#map.get(key)
    if (item !== undefined) item[kTick] = ++this.#tick
    return item
  }
}

Implementation: set()

set (key, item) {
  const prev = this.#map.get(key)
  if (prev === item) { item[kTick] = ++this.#tick; return }
  if (prev !== undefined) this.delete(prev)
  if (this.#arr.length >= this.#capacity) {
    const i = (Math.random() * this.#arr.length) | 0
    const j = (Math.random() * this.#arr.length) | 0
    const a = this.#arr[i], b = this.#arr[j]
    this.delete(a[kTick] <= b[kTick] ? a : b)   // swap-remove
  }
  item[kKey] = key; item[kTick] = ++this.#tick; item[kIdx] = this.#arr.length
  this.#arr.push(item); this.#map.set(key, item)
}

Two random choices vs lru-cache

Wins on hits and updates, with zero allocation per operation. lru-cache is faster when every set evicts.
