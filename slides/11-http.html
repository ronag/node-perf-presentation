The HTTP Hot Path

Response building, headers and object shapes

res.write() is not a string builder

Before: one write per fragment
for (const r of rows) {
  res.write('{"id":"')
  res.write(r.id)
  res.write('","rev":"')
  res.write(r.rev)
  res.write('"}\n')
}
// 36,866 writes per response,
// each one a chunk with framing
After: build into a slab, write big chunks
const ID = Buffer.from('{"id":"')   // precomputed
let slab = Buffer.allocUnsafeSlow(256 * 1024), n = 0

function put (b) {
  if (n + b.length > slab.length) flush()
  n += b.copy(slab, n)
}
function flush () {
  if (n) res.write(slab.subarray(0, n))
  slab = Buffer.allocUnsafeSlow(slab.length); n = 0
}   // never reuse a slab: the socket still owns it

Build responses into your own buffer

one res.write() per fragment

−65%CPU per row
262 → 57 msp99 latency
61,442 → 75writes per response

Respect backpressure (write() returning false), flush before waiting on live feeds, and only paste bytes that are already valid JSON.

Production service, 1 KiB documents, 8 CPUs, Node 26

cork() doesn't coalesce

res.cork()
for (const piece of pieces) res.write(piece)
res.uncork()   // still emits every piece as its own chunk
−81 to −91%vs building a slab, and slower than no cork at all

Corking only delays the syscall. Framing and per-write bookkeeping are paid for every piece.

Bring your own ServerResponse

class Response extends http.ServerResponse {
  setHeader (key, val) { this.#h[key] = val; return this } // trusted names
  getHeaders () { return this.#h }                          // no copy
}
http.createServer({ IncomingMessage: Request, ServerResponse: Response }, handler)
node:http
subclass with a plain header object
0.3 nsgetHeaders() vs 30–330 ns for core's defensive copy
70k → 95kreq/s, together with the hot-path fixes that followed

Validate header names in development only; Node still validates when it serializes. Production service measurement.
