Scheduling & Priorities

@nxtedition/scheduler

The problem

One event loopAll work competes equally. A background job can starve a latency-sensitive request.
One FIFO thread poollibuv queues fs, crypto and zlib work in order. High priority waits behind low priority.

Node has no built-in notion of task priority.

Real world: a network share vs a local SSD

50–500 msper SMB read, holding a thread-pool slot the whole time
0.1 msper SSD read, but stuck in the queue behind SMB
const io = new Scheduler({ concurrency: 4 })    // = UV_THREADPOOL_SIZE
const smb = new Scheduler({ concurrency: 3 })   // cap slow work: always leave a slot

await io.run(() => fs.promises.readFile(ssdPath), 'high')
await smb.run(() => io.run(() => fs.promises.readFile(smbPath), 'low'))

Leave a fast lane: limit slow I/O so fast requests always find a free thread.

Latencies from a production service

Priority-based scheduling

import { Scheduler } from '@nxtedition/scheduler'

const scheduler = new Scheduler({ concurrency: 4 })

// from different handlers: priority matters only when all slots are busy
await scheduler.run(() => handleApiRequest(req), 'high')
await scheduler.run(() => processMessage(msg), 'normal')
await scheduler.run(() => generateReport(), 'low')

// highest · higher · high · normal · low · lower · lowest

Starvation prevention

A lottery over an incrementing counter: each level gets half of what's left.

highest50% higher25% high12.5% normal6.25% low3.1% lower1.6% lowest0.8%

Low priority always makes progress; high priority gets exponentially more. (Shares when every level has queued work.)

Cross-Worker scheduling

// main thread
const size = Number(process.env.UV_THREADPOOL_SIZE ?? 4)
const shared = Scheduler.makeSharedState(size)
const WORKERS = 4
for (let i = 0; i < WORKERS; i++) {
  new Worker(new URL('./http-worker.js', import.meta.url), { workerData: { shared } })
}

// each Worker: one concurrency limit for the whole process
const scheduler = new Scheduler(workerData.shared)

Without coordination, every Worker queues into the same process-wide FIFO pool and priorities stop meaning anything.
