Streams

Backpressure and chunk size

stream.setDefaultHighWaterMark

import { setDefaultHighWaterMark } from 'node:stream'

// byte streams created after this call (fs.createReadStream stays at 64 KiB)
setDefaultHighWaterMark(false, 256 * 1024)
Bigger highWaterMarkFewer backpressure stalls and 'drain' round trips; writable streams batch more chunks per writev.
Trade-off: memoryEach stream buffers more. With thousands of concurrent streams it adds up.

Default: 64 KiB since Node 22 (16 KiB before; still 16 KiB on Windows). In-process pipelines barely care.
