The HTTP Hot Path

Response building and header handling

res.write() is not a string builder

One write per fragment, strings or Buffers
res.cork()               // optional: barely helps
for (const r of rows) {
  res.write('{"id":"')
  res.write(r.id)
  res.write('","rev":"')
  res.write(r.rev)
  res.write('"}\n')
}
res.uncork()             // still one chunk per piece
Build a slab, write big chunks
let slab = Buffer.allocUnsafeSlow(256 << 10)
let n = 0
function put (b) {   // strings: slab.write(s, n)
  if (n + b.length > slab.length) flush()
  n += b.copy(slab, n)
}
function flush () {
  res.write(slab.subarray(0, n))
  slab = Buffer.allocUnsafeSlow(256 << 10)
  n = 0   // the socket owns the old one
}

Every write() pays for stream bookkeeping and chunk framing. cork() only saves syscalls.

In production, a streaming JSON feed went from 75K to 349K rows/s (4.7×), with 65% less CPU and p99 from 262 to 57 ms. Respect backpressure, and flush before waiting on a live feed.

Bring your own ServerResponse

class Response extends http.ServerResponse {
  #h = Object.create(null)
  setHeader (k, v) { this.#h[k] = v; return this }   // trusted names
  getHeader (k) { return this.#h[k] }
  removeHeader (k) { delete this.#h[k] }
  getHeaders () { return this.#h }                    // no copy
  writeHead (status, headers = this.#h) { return super.writeHead(status, headers) }
}
http.createServer({ ServerResponse: Response }, handler)
