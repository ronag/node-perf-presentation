Pointer compression: the fine print

4 GiB heap per isolateEach Worker gets its own cage, so a process with Workers can still use more in total.
A different addon ABIPrebuilt .node binaries for stock Node crash: rebuild native addons. N-API addons work; old V8-API addons don't.
Some code gets slowerDecompressing pointers costs a little on pointer-heavy hot loops: JSON.stringify escaped strings 1.8 MiB −31%, JSON.stringify 512-value batch −16%.

Memory is what you pay for. This is the single biggest memory win we have, and production runs it.

How to build it

# compiler wrapper adds: -O3 -march=x86-64-v3 -mtune=znver3 [-fprofile-generate | -fprofile-use=…]
ENV CC=/usr/local/bin/cc-wrap CXX=/usr/local/bin/c++-wrap
RUN git apply v8-copy-array-buffer-view-bytes.patch

RUN ./configure --enable-lto --experimental-enable-pointer-compression \
 && NODE_PGO=generate make -j"$(nproc)"                     # 1. instrumented build
RUN ./out/Release/node train.mjs                             # 2. run the corpus (120 s)
RUN llvm-profdata merge --weighted-input=16,json.profdata … -o node.profdata
RUN make distclean && ./configure --enable-lto … \
 && NODE_PGO=use make -j"$(nproc)"                          # 3. optimized build
RUN make test-ci                                             # it's your runtime now: test it

Two full compiles plus training: hours, not minutes. Cache them as Docker layers and rebuild per Node release.
