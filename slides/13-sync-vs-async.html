V8 Fast API & Sync Methods

Crossing into C++, and when not to leave the thread

V8 Fast API calls

Normal native callJS → V8 → C++ → V8 → JS: argument conversion, handle scopes, a trip through the runtime.
Fast API callJS → C++, called directly from TurboFan-compiled code when the argument types are known.
Fast in Node 26 buf.copy, compare, swap16/32/64, Buffer.byteLength, isUtf8, isAscii, performance.now, hrtime, URL.canParse, timingSafeEqual, zlib.crc32
Not Fast API fs.*Sync, buf.fill, TextEncoder.encodeInto. Sync fs is fast because it skips the thread pool, not because of the call.

And native isn't free: Buffer.compare on a 5-byte slice took 84 ns, a JS byte loop 2.85 ns.

The async price is a thread-pool round trip, and the OS sets it: thread wake-ups are much slower on macOS.

When is sync OK?

Worker threadsNo main event loop to block
StartupNo requests to block yet
Page cache / SSDMicroseconds, not milliseconds
With yieldingStay responsive (see later)

Sync is the fastest path for useful work. It hurts only when you wait on something slow. Many “I/O” calls hit OS caches and return immediately.

Sync in Workers: hashing files

// worker.js: plain sync code, off the main thread
export default function ({ filePath }) {
  const fd = fs.openSync(filePath, 'r')
  try {
    const hash = crypto.createHash('md5')
    const buf = Buffer.allocUnsafeSlow(128 * 1024)
    let n
    while ((n = fs.readSync(fd, buf)) > 0) hash.update(buf.subarray(0, n))
    return hash.digest('hex')
  } finally { fs.closeSync(fd) }
}
// main.js
const pool = new Piscina({ filename: new URL('./worker.js', import.meta.url).href })
const hash = await pool.run({ filePath })

benchmarks/file-hash-worker.mjs: 128 MB, sync 140 ms vs async 150 ms, and no Promise per chunk
