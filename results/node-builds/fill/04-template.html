Step 2: link-time optimization

./configure --enable-lto   # inline and optimize across Node, V8 and every dependency
B_STEP_LTO_ROWS

On its own: B_GEO_LTO. Inlining across files cut JSON.parse's instructions by 3%, but the bigger hot path misses the instruction cache 29× more often, so it got slower. PGO lays hot code out again (step 5).

Geomean over B_NMETRICS workload metrics: B_GEO_LTO · our Clang 20 build vs the official binary: B_GEO_C20 (the control) · EPYC 9355P · Node 26.10

Costs: ~5.5 GiB RSS per link and a slow rebuild loop. perf stat, small-object JSON.parse, Clang 20 without vs with LTO: instructions per parse −3.3% (8,849 → 8,554), IPC 5.35 → 5.15, front-end idle 2.6% → 7.1%, L1 I-cache misses 0.24 → 6.8 per parse. On the 1.8 MiB escaped payload the instruction count is identical and IPC drops 2%: layout, not codegen.

Step 4: a newer compiler

CC=clang-23 CXX=clang++-23 ./configure   # the official 26.10 binary: Clang 20.1
B_STEP_C23_ROWS

B_C23_TEXT

Geomean over B_NMETRICS workload metrics: B_GEO_C23 · EPYC 9355P · Node 26.10 · median of 8 interleaved runs

Why -mno-gather: Clang 23's SLP vectorizer turns zlib's CRC32 table loop into AVX-512 gathers, which are microcoded and slow on Zen. LLVM's cost model treats "has AVX-512" as "has fast gathers" (upstream: PR #206506 closed unmerged, PR #212997 open). -fno-slp-vectorize also fixes it but turns SLP off everywhere. Even without gathers, Clang 23 runs that loop ~10% slower than Clang 20. Trap: configure doesn't pass your CFLAGS to V8, so inject flags with a compiler wrapper and check they landed (we count zmm and vpgather instructions in the binary).

How to build it

# compiler wrapper adds: -O3 -march=znver5 -mtune=znver5 -mno-gather [-fprofile-generate | -fprofile-use=…]
ENV CC=/usr/local/bin/cc-wrap CXX=/usr/local/bin/c++-wrap
RUN git apply v8-copy-array-buffer-view-bytes.patch

RUN ./configure --enable-lto --experimental-enable-pointer-compression \
 && NODE_PGO=generate make -j"$(nproc)"                     # 1. instrumented build
RUN ./out/Release/node train.mjs                             # 2. run the corpus (120 s)
RUN llvm-profdata merge --weighted-input=16,json.profdata … -o node.profdata
RUN make distclean && ./configure --enable-lto … \
 && NODE_PGO=use make -j"$(nproc)"                          # 3. optimized build
RUN make test-ci                                             # it's your runtime now: test it

Two full compiles plus training: hours, not minutes. Cache them as Docker layers and rebuild per Node release.
